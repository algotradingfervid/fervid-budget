| grid-htmx-1, blocking: TC-G-042 failed with `htmx:sendAbort` / `htmx:afterRequest` console errors | fixed | This happened when a user typed a search and pressed Enter or Apply inside the 350ms live-search pause. Enter first commits a `change` and then submits, and the pause fires the same search a third time. `hx-sync="this:replace"` aborted the request in flight, and htmx logs every abort as a console error. The form now uses `hx-sync="this:queue last"`, so no request is aborted. It is also marked `data-skip-shown-filters`. For that form, a small `htmx:configRequest` handler in `fervid-app.js` drops a request whose filters were the last ones sent. It also drops a live request (one that is not a submit) whose filters the URL already shows. Result: one gesture sends one request and pushes one history entry. TC-G-042 was not changed. | TC-G-042 passed 3 of 3 runs on fresh servers, and the full audit-g suite passed (56). New e2e "grid-htmx-1: search then Enter logs no errors…" checks no console errors and exactly one grid request, at 1440 and 390. |
| grid-htmx-1, minor: after Back or Forward the controls did not match the grid | fixed | htmx's page snapshot keeps the rows but not the values typed or picked in the controls.

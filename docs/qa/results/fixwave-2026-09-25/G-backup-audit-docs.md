# Fix wave 2026-09-25 — cluster G: backup, audit log, docs

Each defect was reproduced first by a test that failed on `main`, then fixed at the root.
Browser checks ran against a fresh `--seed` server on 127.0.0.1:5160, at 1440px and 390px.

| Defect | Status | How it was fixed | Tests |
|---|---|---|---|
| backup-1 (BV50) restore over a DB with a live WAL served the old data | fixed | `RestoreBackup` (`internal/store/backup.go`) moves the target's `-wal` and `-shm` aside with the old database before the swap, puts them back on rollback and deletes them on success. SQLite can no longer replay the pre-restore WAL over the restored file. | `TestRestoreBackupOverDatabaseWithLiveWALServesTheBackup` (failed on main: "stale -wal left beside the restored database") |
| backup-2 (BV48) no automated daily backup | fixed | New `store.DailyBackup` (`internal/store/backup_schedule.go`), started by `cmd/server` in serve mode beside the reminder scheduler, in its own goroutine and on the shutdown context. It checks on start and every 10 minutes. Once the local clock passes `FERVID_BACKUP_HOUR` (default 2, invalid values fall back to 2), it makes the day's backup, unless a backup stamped after that hour already exists. That rule makes it idempotent across ticks, restarts and manual backups. It logs `daily backup created` or `daily backup failed`, then prunes. | `TestDailyBackupRunsOncePerDayAfterTheConfiguredHour`, `TestDailyBackupCountsOnlyBackupsMadeAfterTheHourToday`, `TestDailyBackupPrunesWithTheRetentionRules`, `TestDailyBackupSchedulerRunsOnStartAndStopsOnCancel`, `TestLoadDefaultsAndEnvironmentOverrides` (extended) |
| backup-3 (BV49) retention kept no monthly backups | fixed | `PruneBackups(dir, keepDays, keepMonths, now)` keeps every backup younger than `FERVID_BACKUP_KEEP_DAYS` (30). It also keeps the newest backup of each of the previous `FERVID_BACKUP_KEEP_MONTHS` (12, new) calendar months. A backup's age comes from the timestamp in its folder name; a name without a timestamp falls back to the folder's mtime. The two callers (`backupCreate` and `--backup`) pass the new setting. | `TestPruneBackupsKeepsThirtyDaysAndTheNewestBackupOfTwelveMonths` and `TestPruneBackupsAgesByTheTimestampInTheName` (both failed on main with the old signature: 31 kept instead of 42) |
| audit-1 (BV35) no date filter; list silently cut at 200; action/actor only searched the newest 1000 rows | fixed | New `Store.AuditPage(AuditQuery)` applies entity, id, action, actor (case-insensitive substring) and a from/to range in SQL over the whole log, and returns the total. `/audit` has From/To date inputs (local days, inclusive) and shows 100 rows per page. When there are more, it shows "Showing a–b of N" with ← Newer / Older → links that keep every filter. A reader whose request scope is narrower than `all` gets the scope applied before paging, so the counts stay correct. | `TestAuditLogFiltersEveryRowAndPages`, `TestAuditLogFiltersByDate` (both failed on main: the create row was unreachable and the form had no date control) |

- **backup-2 and backup-3:** 400 dated `backup-*` folders were pre-created, one per day for 400 days.

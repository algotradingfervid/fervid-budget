# Fix wave 2026-09-25 — H: mobile layout

One root cause in the shared layout CSS (`web/static/fervid-ds.css`), fixed once. No template changes.

| Defect | Status | How it was fixed | Tests |
|---|---|---|---|
| ux-mobile-1 | fixed | Below 860px `--page-gutter` was `0px`, based on the belief that each narrow block set its own 14px inset. Only `.page-banner` and `.gridhead` did. The gutter is now `16px` there, so `.page-inner` insets every block. The two full-width bands already cancel the gutter and add it back as padding, and they now use `var(--page-gutter)` in place of a hand-written 14px, so their text lines up with the content. A 16px gutter made the column narrower, which exposed a second bug: an `.action-bar` button whose label contains a person's name ("Save and notify …") could not wrap and ran off the bar. It now wraps at phone width. | `ux.spec.ts` › "every navigable screen is reachable, fits, and is accessible" (new gutter check: every direct child of `.page-inner` is at least 16px from both edges of `main.page`, at 1280 and 393) |
| rbac-11 | fixed | The phone half is the same gutter fix. For desktop, `.page-inner` now has `padding-top: var(--page-gutter)`, so a page that opens on a card (request or payment detail) no longer draws that card along the top of the window. A banner or grid header that opens the page cancels the top padding with a negative margin, so it still meets the top edge. | `ux.spec.ts` › "request detail and the deactivation warning keep the gutter at 390 and 1440"; the nav walk also checks that the first block is at least 16px from the top, and that an opening band sits flush at the top |
| deactivation-1 | fixed | `.checkline` had `white-space: nowrap`, so a label was always as wide as its sentence. It now uses `white-space: normal; max-width: 100%`, so the confirmation text wraps inside the column. Short labels, such as "Active" in the heads table, still fit on one line. | `ux.spec.ts` › "request detail and the deactivation warning keep the gutter at 390 and 1440" (no sideways scroll, and the confirm label ends inside the viewport, at 390 and 1440) |

No existing test encoded the old behaviour. Before the fix, `request-workflow.spec.ts` (mobile) was the one spec that failed once the gutter was added: the long "Save and notify" button overflowed. The `.action-bar .btn` wrap rule fixes that, and the spec was left unchanged.

Browser check: a Playwright walk of every sidebar screen, plus a request's detail page, `/requests/new`, `/payments/new?request=`, `/vendors/1` and the head-deactivation warning, at 390 and at 1440, as admin, with a Manager's `/approvals`, request and home screens at 390. At 390, on every screen the smallest block inset was 16px and there was no sideways scroll. At 1440 the smallest inset was 28px. Request detail starts 16px below the top at 390 and 28px below at 1440. The confirm label wraps to two lines at 390.

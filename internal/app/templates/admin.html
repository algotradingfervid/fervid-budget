No backups created yet. An operator with Create Backup permission can create one.

Restore safely with your operator

  1. Agree the recovery point and expected data loss. Newer changes will be replaced.
  2. Copy the selected backup folder to protected storage. Verify it contains fervid.db, attachments/ and manifest.json.
  3. Test the restore into a separate database and attachment directory. Compare expected records, totals and attachment downloads before touching production.
  4. Stop the application and its schedulers. Preserve the current database, SQLite sidecar files and attachment directory together as a rollback copy.
  5. Run the selected command on the server. The command targets database {{.BackupDBPath}} and attachments {{.BackupAttachmentPath}}. For an installed binary, replace go run ./cmd/server with that binary.
  6. Restart with the same configuration. Sign in and verify totals, requests and attachments. If validation fails, stop and have the operator restore the preserved rollback copy.

Configuration and external secrets are managed separately. Record the last successful restore test in your operations log; “files present” is not evidence of recoverability.
